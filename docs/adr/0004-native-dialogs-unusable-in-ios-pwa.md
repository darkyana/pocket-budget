# 0004 iOS PWA 内禁用原生对话框：一律用 Sheet / ConfirmButton

iOS 把应用装成 standalone PWA 后，`prompt()` / `confirm()` / `alert()` 等原生对话框行为不可靠（不弹出或表现异常），且只在安装形态下坏——浏览器里调试一切正常，问题被推迟到真机。因此本应用不使用任何原生对话框：确认用两段式 `ConfirmButton`（先点进入待确认，限时内再点才执行），输入与内容展示用底部弹层 `Sheet`。后续新增任何需要确认或输入的交互，一律复用或扩展这两个组件，不得直接调用原生对话框 API。

## Consequences

- 缺陷只在 iOS 安装形态复现，桌面浏览器与开发环境不可见，测试（纯逻辑、无 jsdom）也无法覆盖——此约束是防止这类「真机才坏」回归的唯一护栏。
- 这是**一类约束**而非单点 workaround：所有未来的对话框场景都受它约束，新增交互前先看这里，而不是写一句 `confirm()` 图省事。
