# 0003 按日期派生的视图需要分钟唤醒

所有按日/按月的派生视图（今日页、月历、日期筛选）都在渲染时从 `new Date()` 实时计算；组件只在状态或 store 变化时重渲染，页面若无人交互地开着跨过零点，「今天」就僵在昨天、数字全错且无任何报错。约定：承载日期派生视图的页面组件必须带分钟唤醒——一个 60 秒一次的强制重渲染（`src/app/pages/Today.tsx` / `QuickRetro.tsx` 现行模式）。否掉的两个替代：定时到零点整（移动端挂起/节流下不可靠，且处理唤醒重排很繁琐）；仅靠 visibilitychange（覆盖不了亮屏跨零点）。分钟 tick 对这些情况天然免疫——挂起期间 interval 停走，唤醒后下一个 tick 立刻用新时钟重算。

## Consequences

- 每分钟一次冗余渲染是接受的代价（derive 为纯实时计算，成本可忽略）；零点后最多滞后 60 秒翻页，对账本无感。
- 新增日期派生页面时照此约定带上唤醒；删除「看似无用」的 tick state 之前先读本 ADR。
- 现状 Records / Settings 也有 `new Date()` 但尚未带唤醒——补齐是单独的实现票，不在本 ADR 范围。
